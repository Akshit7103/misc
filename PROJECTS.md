## 🔑 Cross-Cutting Engineering Patterns

- **"AI reasons, code decides."** A repeated design principle (Gap Analysis, IVR/ERA, Nomura, Model Validation): the LLM extracts and reasons, but scores, decisions, and arithmetic are computed **deterministically in Python** for auditability.
- **Graceful degradation.** Nearly every AI tool falls back to heuristics/mock reasoners or local models when the API key or Ollama is unavailable, so a run never hard-fails.
- **Human-in-the-loop.** Four-eyes SAR approval, analyst disposition workflows, L1/L2/L3 escalation, and reviewer overrides recur across the compliance tools.
- **Regulator-ready output.** Styled Excel + branded PDF/Word exports and immutable audit trails are near-universal deliverables.
- **Config-as-single-source-of-truth.** Rules engines, rate tables, thresholds, and regulatory parameters are externalized so business logic can be tuned without code changes.

## A1. AML — Compliance Ops POC ("Bretton")
**Folder:** `AML/bretton-poc`
**One-line summary:** An AI-agent financial-crime compliance console that runs concurrent sanctions / PEP-EDD / AML / KYB agents per case, streams their reasoning live, aggregates a risk score, and produces human-in-the-loop dispositions and SAR PDFs.
**Domain / Category:** AML / Financial Crime Compliance — case investigation & transaction monitoring.
**Problem & Business Context:** Bank compliance teams face a flood of sanctions/PEP/AML alerts that each require manual evidence-gathering across many data sources before a disposition. This POC demonstrates an "AI L1 analyst" that pulls evidence from OFAC, OpenSanctions, Wikidata, Google News and the transaction ledger, scores risk, drafts a regulator-style narrative, and auto-clears clean alerts while escalating real ones.
**What It Does:** An analyst lands on a dashboard of pre-seeded alerts, opens a case, and watches three/four agents run concurrently in a live SSE timeline (each emitting step-by-step evidence). The system computes an aggregate risk score, drafts an investigation narrative, and lets the analyst approve/escalate/file-SAR. A manual screening page screens any free-text name; a continuous background loop scans transactions and generates new AML alerts; a Customer 360 view shows profile, accounts, 12-month volumes and KYC docs; KYC documents can be uploaded for LLM field extraction and cross-referencing.
**Tech Stack (detailed):** Python; FastAPI 0.115.0 + Uvicorn[standard] 0.30.6 (async); Jinja2 3.1.4 server-rendered templates + vanilla JS; SQLAlchemy 2.0.35 async ORM over aiosqlite 0.20.0 (SQLite). LLM abstraction over **OpenAI** (openai 1.51.0; models `gpt-4o-mini` "fast" and `gpt-4o` "smart") OR **Ollama** local (`mistral`), swappable by `LLM_PROVIDER`. rapidfuzz 3.10.0 (fuzzy name matching), httpx 0.27.2 (async external calls), feedparser 6.0.11 + beautifulsoup4 4.12.3 + lxml 5.3.0 (Google News RSS / OpenSanctions HTML / Wikidata parsing), reportlab 4.2.5 + pypdf 5.1.0 (SAR PDF), apscheduler 3.10.4, python-multipart, pydantic 2.9.2 / pydantic-settings 2.5.2.
**Architecture & Data Flow:** FastAPI app (`app/main.py`) with a `lifespan` that inits the DB and launches an asyncio `monitoring_loop` background task. Per case, `app/agents/orchestrator.py` loads case→alert→customer, then `asyncio.create_task` runs Sanctions + AML + (PEP-EDD for persons | KYB for companies) concurrently via `asyncio.gather`. Each agent emits events through per-case in-memory `asyncio.Queue`s consumed by the SSE endpoint (`/api/stream/{case_id}`). Findings persist as `Evidence` rows; the orchestrator aggregates a risk score, calls the "smart" LLM for a narrative, applies L1 auto-triage, and writes `AuditLog` entries. External calls are TTL-cached in a `cache_entries` SQLite table.
**Key Algorithms / Logic / Formulas / Thresholds:**
- **Structuring detector** (`app/utils/patterns.py`): cash+inbound deposits where `0.85×threshold ≤ amount < threshold` (threshold $10,000), clustered within a 14-day window, min 4 deposits.
- **Round-trip:** out/in pairs to same counterparty ≥ $5,000, return within 7 days, amount tolerance 10%, ≥2 matched pairs.
- **Velocity spike:** recent-7-day daily volume / prior-baseline daily volume; fires when `ratio ≥ 5.0` AND ≥5 recent tx AND recent daily ≥ $5,000 (needs ≥10 prior tx).
- **High-risk geography:** counterparty country in (RU, IR, KP, SY, AF, VE), ≥3 tx AND total ≥ $25,000.
- **AML agent fallback scoring:** structuring→85, round_trip→75, velocity→60, geography→50; verdict `sar_recommended` ≥75, `monitor` ≥40, else `clear`.
- **Aggregate risk:** `max(sub_scores)`; if AML ≥60, boosted to `min(100, max(aggregate, aml×0.95 + sanctions×0.1))`.
- **L1 auto-clear:** only if aggregate <20 AND sanctions score 0/clear AND not PEP AND adverse-media severity not medium/high AND AML score <20 with no patterns.
- **Sanctions:** OFAC SDN fuzzy match (rapidfuzz) threshold 85, top-5 candidates; LLM (fast) resolves true/false positive.
- **TM loop:** every 120 s, 90-day lookback, dedup key `(customer_id, pattern_name)`.
**API Endpoints / Routes:** HTML: `GET /`, `/case/{case_id}`, `/screening`, `/customer/{customer_id}`, `/customers`, `/health`. API: `GET /api/alerts`, `GET /api/alerts/{id}`, `POST /api/alerts/{id}/open-case`; `GET /api/cases`, `GET /api/cases/{id}`, `POST /api/cases/{id}/disposition`; `POST /api/screening`; `GET /api/stream/{case_id}` (SSE); `GET /api/customers`, `GET /api/customers/{id}`; `POST /api/documents/upload/{customer_id}`; `GET /api/exports/sar/{case_id}` (SAR PDF).
**Data Model / Storage:** SQLite `data/compliance.db`, async SQLAlchemy models (`app/models.py`): `customers`, `accounts`, `transactions` (amount, counterparty, counterparty_country, tx_type wire/ach/cash/check, direction in/out), `alerts` (alert_type sanctions|pep|aml|manual), `cases` (status open|investigating|completed|closed, disposition cleared|escalated|sar, narrative), `evidence` (source ofac|opensanctions|wikidata|gnews|tx_analysis|llm, payload JSON), `audit_log`, `kyc_documents` (extracted_text, extracted_fields JSON, review_result JSON), `cache_entries` (key, value JSON, expires_at).
**Key Features:** Concurrent multi-agent per-case investigation; live SSE agent timelines with case replay; continuous transaction-monitoring alert generation; L1 auto-triage; Customer 360; SAR PDF export; KYC document intelligence; provider abstraction (OpenAI↔Ollama); TTL external-call cache; full audit log.
**Project Structure (key files):** `app/main.py`, `app/monitoring.py` (TM loop), `app/utils/patterns.py`, `app/agents/{orchestrator,sanctions,pep_edd,aml,kyb,kyc_docs}.py`, `app/data_sources/{ofac,opensanctions,wikidata,gnews,opencorporates}.py`, `app/llm/{base,openai_provider,ollama_provider}.py`, `app/routers/{alerts,cases,screening,stream,customers,documents,exports}.py`, `app/models.py`, `app/db.py`, `app/config.py`, `app/seed.py` (synthetic data incl. ## A2. AML/TF Automation Tool — EWCRA Risk Calculator
**Folder:** `AML TF Automation Tool` (primary code under `New Folder (2)1/ewcra-tool`; a second near-identical copy under `AML Tool/ewcra-tool`)
**One-line summary:** A live, fully-editable web calculator that faithfully reproduces an Enterprise-Wide Compliance Risk Assessment (ML/TF) Excel workbook — inherent risk, product risk, compliance-theme scoring, and the residual-risk matrix — with Excel/PDF export.
**Domain / Category:** AML/CFT — Enterprise-Wide Risk Assessment (EWRA/EWCRA) automation.
**Problem & Business Context:** Banks run an annual enterprise-wide ML/TF risk assessment that normally lives in a fragile multi-sheet Excel workbook with hand-wired formulas. This tool turns that workbook into a reproducible web app where every factor, sub-factor, weight, threshold and the residual matrix are editable and results recompute live, producing a board/regulator-ready report.
**What It Does:** A user edits an assessment (segments, factors/sub-factors, products, compliance themes) in an SPA; the backend recomputes inherent scores per segment, product ratings, compliance-theme ratings, the residual-risk matrix, and a bank-level aggregate blended by customer-count / txn-volume / txn-value shares. Weights show live "Σ 100% ✓/⚠" warnings; work autosaves to the browser with undo/redo; assessments save server-side; a formatted multi-sheet `.xlsx` (RAG-coloured) and a print-to-PDF report can be exported.
**Tech Stack (detailed):** Python; FastAPI + Uvicorn (minimal `requirements.txt`: `fastapi`, `uvicorn`, `openpyxl`); vanilla HTML/CSS/JS SPA (`static/index.html`, `app.js`, `styles.css`); openpyxl for `.xlsx` export (`report.py`). No LLM, no DB — assessments are JSON documents on disk. App title: "MIRA — Financial Crime Risk Assessment".
**Architecture & Data Flow:** `engine.py` is a pure, stateless calculation engine (single source of truth). `app.py` (FastAPI) serves the SPA and exposes `/api/calculate` (POSTs the whole assessment JSON, returns all derived values), sample/blank loaders, save/load/list/delete persistence under `data/saved/*.json`, and `/api/export/xlsx` (streams openpyxl workbook via `report.build_workbook`). `extract_sample.py` regenerates the sample dataset from the source workbook; `test_engine.py` validates the engine (38 checks) against known workbook values.
**Key Algorithms / Logic / Formulas / Thresholds:**
- **Inherent sub-factor scoring:** `ratio` mode = numerator/denominator → response %, scored 1 (≤ low_max, default 0.05), 3 (> high_min, default 0.10), else 2; `manual` mode = clamped 1–3.
- **Factor score** = Σ(sub_score × sub_weight); **segment inherent** = Σ(factor_score × factor_weight).
- **Inherent bands** (default): Low ≤ 1.66, High ≥ 2.33, else Medium.
- **Product (Appendix 2) scoring:** per risk-factor group, single-question → Yes=3; multi-question → count of Yes (0,1,2, or ≥3→3); total mapped by **product bands** High ≥ 12, Medium ≥ 7, else Low.
- **Compliance themes:** control scores 1–3; "Effectiveness" sub-factors auto-weighted 0.5, non-effectiveness split the remaining 0.5 evenly (or manual weights); **compliance bands** Satisfactory ≤ 1.66, Deficient ≥ 2.33, else Needs Improvement.
- **Bank roll-up:** per-segment weight = mean of customer-count/txn-volume/txn-value shares (auto) or manual, normalised to sum 1; bank inherent score = Σ(weight × segment inherent).
- **Residual matrix** (Inherent × Compliance → residual): e.g. Low/Sat=Low, Low/Deficient=Medium, Medium/Deficient=High, High/Deficient=High.
**API Endpoints / Routes:** `GET /` (SPA), `GET /api/sample`, `GET /api/blank`, `POST /api/calculate`, `POST /api/export/xlsx`, `GET /api/assessments`, `GET /api/assessments/{aid}`, `POST /api/assessments`, `DELETE /api/assessments/{aid}`; static at `/static`.
**Data Model / Storage:** No database. One assessment = JSON doc with `meta`, `config` (`inherent_bands`, `compliance_bands`, `product_bands`, `product_risk_factors[]` (10 factors incl. Third Party, Transparency/Anonymity, Cross-Border, Structuring, Known FCC Typologies), `residual_matrix`, `bank_weight_mode`), `segments[]` (each `factors[]`→`subfactors[]`, `products[]`, `bank_weighting`), and `compliance.themes[]`. Sample: "Demo Bank FCRA" (5 segments, 7 compliance themes). Saved files under `data/saved/`.
**Key Features:** Live recompute; fully editable framework; Excel export with RAG colouring; print-to-PDF; per-sub-factor rationale; browser autosave; undo/redo (Ctrl+Z/Y); weight-sum warnings; residual heat-map + per-segment bars; 38-check regression tests.

**Architecture & Data Flow:** `POST /api/upload` saves to `uploads/{uuid}{ext}`, computes SHA-256, inserts a `Document` row, and enqueues `orchestrator.run_all_checks(doc_id)` as a FastAPI `BackgroundTask`. PDFs are rendered to PNG (page 0, 200 dpi) for image-based checks.
**Key Algorithms / Logic / Formulas / Thresholds — every forensic check:**
1. **Duplicate detection** (weight 1.0): SHA-256 exact (conf 0.98) → perceptual a/p/d/w-hash Hamming; `DUPLICATE_HASH_THRESHOLD=10` (conf 0.90), `DUPLICATE_NEAR_THRESHOLD=15` (warning conf 0.55). Stores `ImageHash` + `DuplicatePair`.
2. **Metadata analysis** (0.6): EXIF/PDF metadata; flags 30+ editing tools (photoshop, gimp, canva, acrobat, foxit, sejda, smallpdf, ilovepdf…), date mismatches, GPS. `confidence = min(0.3×flags, 0.95)`; failed if >0.5.
3. **ELA** (0.8): re-save at `ELA_QUALITY=95`, amplify diff (`ELA_SCALE=15`), heatmap; suspicious pixels = `gray > mean + ELA_STD_THRESHOLD(2.0)·std`; **failed** if adjusted_ratio>0.15 & regional_variance>20 (conf up to 0.90), **warning** if >0.05 or (ratio>0.10 & var>15).
4. **Copy-move forgery** (0.9): ORB `ORB_FEATURES=2000`, BFMatcher knn(k=5) self-match (distance≤40, spatial>30 px), DBSCAN `DBSCAN_EPS=30`, `DBSCAN_MIN_SAMPLES=5`; **failed** if ≥1 cluster, `conf = min(0.4+0.15·clusters, 0.95)`; overlay drawn.
5. **AI-generation detection** (0.7): 5 signals — EXIF absence (softened for PNG/"screenshot"), noise uniformity (Laplacian CV<0.2), FFT radial high-freq ratio (<0.3), color-channel correlation (>0.985), texture/edge density (Sobel <0.02). Weights noise 0.25, freq 0.20, channel 0.20, texture 0.20, exif 0.15. **failed** >0.55, **warning** >0.35.
6. **PDF edit detection** (0.7): `%%EOF` count (>2 strong, >1 flag), `xref` count; producer/creator vs `KNOWN_GENERATORS` allowlist (wkhtmltopdf, chrome, libreoffice, uber/ola/swiggy/zomato…) vs `EDITING_TOOLS`; suspicious annotations (Redact/Stamp/FreeText/Ink/Polygon); filled form widgets. **failed** if ≥3 flags, **warning** ≥1.
7. **QR validation** (0.5): pyzbar decode; if QR present, Tesseract OCRs and compares QR tokens (len>3) to OCR text — **warning** if match_ratio<0.3.
8. **Keyword analysis** (0.8): OCR/PDF text scanned against `data/keywords.json` — **high-risk**: personal_expenses (gift cards, itunes, netflix…), alcohol_tobacco; **medium**: entertainment, luxury (louis vuitton, rolex…), suspicious_amounts; **low**: non_business. high→failed `min(0.5+0.15·n,0.95)`, medium→warning.
9. **Amount extraction** (0.6): regex for `$`, USD/INR/EUR/GBP/CAD/AUD, total-adjacent, standalone `1,234.56`; largest total-candidate primary; historical **z-score** vs prior primary_amounts (n≥5, std>0): z>3 → failed (conf 0.7), z>2 → warning; **high-amount flag** if primary>$5000 (warning conf 0.4); values 0.01–1,000,000.
- **Composite risk (`_compute_composite_risk`):** weighted avg of flagged checks' confidences (passed checks add `weight×0.3` to denominator); **corroboration boosts** — metadata+ELA +0.15, ELA+copy-move +0.20, metadata+AI +0.10, keyword+amount +0.15, duplicate+metadata +0.10; **contradiction dampening** (one flags, paired passes) = −0.5×boost; final clamped [0, 0.98]. `overall_status = "flagged"` if any check failed/warning else `passed`.

## C1. ECL Automation — IFRS 9 / Ind AS 109 Expected Credit Loss Engine
**Folder:** `ECL Automation`
**One-line summary:** A FastAPI web tool that ingests loan-level Days-Past-Due (DPD) history plus IMF WEO macro data and computes forward-looking, scenario-weighted Point-in-Time Probabilities of Default via a Vasicek/Basel model, emitting a fully-formatted multi-sheet Excel workbook and interactive dashboard.
**Domain / Category:** Credit Risk / IFRS 9 · Ind AS 109 Expected Credit Loss (ECL) / PD modelling.
**Problem & Business Context:** IFRS 9 / Ind AS 109 require lifetime, forward-looking, macro-conditioned ECL. Building the transition matrices, Observed Default Rates (ODR), Through-the-Cycle (TTC) PDs, macro Z-factors and scenario-weighted PIT PDs by hand in Excel is slow and error-prone. This tool automates the full PD engine from raw monthly DPD snapshots and produces an auditable, banker-formatted workbook mirroring a manual ECL model.
**What It Does:** The user uploads two Excel files — a DPD file (loan-level monthly delinquency states) and an IMF WEO macro file — sets three knobs (macro shock, transition-matrix start year, historical cutoff year), clicks compute, sees results across interactive dashboard tabs (transition matrices, ODR trend/heatmap, MAV Z-factors, MEV scenarios, Vasicek PD, survival/PIT PD, sensitivity), then downloads the formatted `.xlsx` (10 sheets) and optionally generates a branded PDF report.
**Tech Stack (detailed):** Python 3.11.11. Backend: FastAPI 0.115.12 + Uvicorn 0.34.2, Jinja2 3.1.6, python-multipart 0.0.20. Numerics: pandas 2.2.3, numpy 2.2.6. Excel: openpyxl 3.1.5 (hand-styled cells). PDF: fpdf2 2.8.3; matplotlib 3.10.1 for report charts. Frontend: vanilla JS + Chart.js 4.4.7 (jsDelivr CDN). Notably, scipy is deliberately avoided — a pure-Python `_Norm` class reimplements `norm.cdf` (Abramowitz & Stegun) and `norm.ppf` (Acklam-style rational approximation) to eliminate the ~30MB scipy/Fortran dependency.
**Architecture & Data Flow:** `main.py` (FastAPI) receives uploads → writes to a temp dir → instantiates `ECLEngine(dpd_path, weo_path, output_path, config)` → `engine.run()` executes a 10-step pipeline → writes styled `.xlsx` to `outputs/ECL_Output_{job_id}.xlsx` and returns a JSON results bundle (`_collect_results`) for the dashboard → temp dir cleaned in `finally`. The Excel is downloadable by `job_id`; a separate `/api/report` endpoint renders a PDF via `pdf_report.generate_report`.
**Key Algorithms / Formulas / Methods (exhaustive & precise):**
- **DPD state model:** FROM states `{0,1,2,3,4}`; TO states add `{WO, ARC, Closed}`. Buckets: `0 / 1-30 / 31-60 / 61-90 / 90+`. Default states = `{4, WO, ARC}` (bucketed `{90+, WO, ARC}`).
- **Transition matrices:** per calendar month, for each consecutive year pair `(yr, yr+1)` matching column pattern `DPD_<Mon>-<YY>`, counts of state migrations and per-from-state default rate = defaults / total.
- **Observed Default Rate (ODR):** aggregated across all months of a from-year; ODR = Σ(defaults into 90+, WO, ARC) / Σ(all observations). Partial-year (<12 months) flagged amber; no-data flagged N/A.
- **TTC PD:** `ttc[bucket] = mean(ODR per grade over odr_display_years)` (default 2020–2024, n=5); the `90+` grade is hard-set to TTC = 1.0.
- **Basel II Retail IRB asset correlation:** `W = (1 − e^(−35·PD)) / (1 − e^(−35))`; `rho = 0.03·W + 0.16·(1−W)`, bounded `[0.03, 0.16]`; if PD ≥ 1.0, rho = 0.03.
- **Macro (MAV) processing:** IMF WEO series for 5 MEVs — `LUR` (Unemployment), `NGDP_RPCH` (GDP), `PCPIPCH` (Inflation), `GGX_NGDP` (Govt Expenditure), `GGXWDG_NGDP` (Govt gross debt). Historical 2019–2027; extrapolated 2028–2032 via linear `np.polyfit` (degree 1) over the 2025–2027 trend window. LTM = mean, SD = population std (ddof=0) over calibration 2019–2025 (n=7).
- **Z-factor:** `Z = (Value − LTM) / SD`; CV = |SD/LTM|. GDP uses hard-coded `GDP_PRECISE = {2025:6.198, 2026:6.265, 2027:6.471}`.
- **Scenario generation (GDP-driven):** shock default ±10%. `Base = Z`, `Upturn = Z + |Z|·shock`, `Downturn = Z − |Z|·shock`.
- **Vasicek unconditional PD:** `PD = Φ( (Φ⁻¹(TTC) − √rho·Z) / √(1−rho) )` per grade/scenario/year over 2025–2032; returns 1.0 if TTC ≥ 1.
- **Survival analysis:** `S₁ = 1 − PD`; cumulative survival = running product of `S₁`.
- **Marginal (PIT) PD:** t₁ marginal = Vasicek PD at t₁; tₙ marginal = `S(tₙ₋₁) − S(tₙ)`. **PIT PD** = Σ over scenarios of `scen_weight · marginal_PD`. **Lifetime PD** = `1 − Σ(scen_weight · cumulative_survival at last year)`.
- **Default scenario weights:** `Base 0.50, Upturn 0.05, Downturn 0.45`.
- Also emits a correlation curve (rho vs PD over 1bp–100% grid).
**API Endpoints / Routes:** `GET /` (dashboard); `POST /api/compute` (multipart `dpd_file`, `weo_file`, `shock` default 0.10, `tm_start_year` 2020, `hist_cutoff` 2024 → JSON results + `download_url`); `GET /api/download/{job_id}` (`ECL_Output.xlsx`); `POST /api/report` (`{data, company, prepared_by}` → PDF); `GET /api/report/{job_id}` (`ECL_Report.pdf`).
**Data Model / Storage:** No database. Inputs parsed from Excel (DPD columns matched by regex `DPD_([A-Za-z]+)-(\d{2})`; WEO read header-less with series matched by IMF code in column index 1). Any finding mutation invalidates caches and triggers `run_clustering()` (daemon thread): `weighted_token_counts` → `build_tfidf` → auto-k → `bisecting_kmeans` → labelling → cache pre-warm.
**Key Algorithms / Formulas / Methods (exhaustive & precise):**
- **Tokenization:** lowercase, regex `\b[a-z][a-z\-]{2,}\b`, remove an extensive domain stop-word set, then unigrams + bigrams.
- **Field weighting (`config.FIELD_WEIGHTS`):** `description ×8, business_justification ×7, model_theme ×2, title ×1, suggested_remediation ×1`.
- **TF-IDF:** sublinear TF `1 + ln(count)`; smoothed IDF `ln((N+1)/(df+1)) + 1`; vocabulary filtered to `df ∈ [1, 0.95·N]`; L2-normalized. Cosine via dot on normalized vectors.
- **k-means:** cosine-distance k-means++ init, 3 restarts, 100 iters, empty-cluster re-seeding; inertia = Σ(1 − cos).
- **Bisecting k-means:** repeatedly split highest-inertia cluster with 2-means until k clusters.
- **Auto-k selection:** data-size-dependent `k_max`; computes **silhouette** (cosine, sampled ≤200) and **Gap statistic** (5 uniform reference datasets, `sd_k·√(1+1/n_refs)`); final k = argmax of blended **`0.55·gap_norm + 0.45·silhouette − 0.002·k`**, with a tie-break toward the standard Gap `Gap(k) ≥ Gap(k+1) − s_{k+1}` elbow when within 0.05.
- **Cluster labelling:** dominant normalized theme + top-2 bigrams by per-cluster TF-IDF; "top signals" = top bigrams+unigrams.
- **Theme normalization (`config.THEME_GROUPS`):** maps free-text themes → `data_quality, documentation, governance, methodology, performance_monitoring, implementation, model_validation`.
- **Search:** query tokenized with bigrams, theme-keyword boosts (+0.5), projected into cached doc TF-IDF space, cosine ranked; best cluster = highest mean member similarity; result cached.

## D5. Financial Incentive Calculator (NACV Incentive Calculator)
**Folder:** `Financial-Incentive-Calculator`
**One-line summary:** A Flask web app that extracts contract terms from a Word (.docx) contract and NACV volumes from an Excel workbook, then computes corporate-card basis-point incentives plus Card-Holder-Days (CHD) performance adjustments and exports a formatted Excel report.
**Domain / Category:** FinTech / commercial-card incentive & rebate calculation.
**Problem & Business Context:** Corporate-card programs pay clients incentives expressed in basis points (bps) against their Net Annual Charge Volume (NACV), with rates that vary by "ticket type" band and an additional adjustment tied to Card-Holder-Days (CHD) performance versus a benchmark. Doing this by hand from a Word contract + an Excel volume file is slow and error-prone. This tool parses both documents, applies the contract's rate tables and CHD rules, and produces an auditable calculation report.
**What It Does:** User opens the upload page, drag-drops a Word contract and an Excel NACV file, optionally types an actual CHD value, and submits. The app parses the CC-NACV rate table and CHD benchmark/rules from the Word doc, reads label/NACV pairs from Excel, computes per-label incentive amounts and a total, computes CHD "Actual" and "CAP" adjustment calcs, renders results, allows re-computing CHD without re-uploading, and offers a multi-sheet Excel export.
**Tech Stack (detailed):** Python 3.11 (runtime.txt `python-3.11.0`). Backend: Flask 3.0.0, Werkzeug 3.0.1. Document parsing: python-docx 1.1.0 (Word tables/paragraphs), pandas 2.1.4 (Excel via `pd.ExcelFile`/`read_excel`), openpyxl 3.1.2 (Excel export via `Workbook`, styles). Production server: gunicorn 21.2.0. Frontend: Jinja2 templates (`upload.html`, `results.html`) with vanilla drag-and-drop. Storage: Flask server-side `session` for results; local `uploads/`. Rotating file logging (`logger.py`).
**Architecture & Data Flow:** Single-process Flask app (`app.py`). Modules: `config.py` (constants/patterns), `parsers.py` (`WordDocumentParser`, `ExcelParser`), `validators.py`, `logger.py`. Synchronous (no async/background).
**Key Algorithms / Logic / Formulas / Thresholds:**
- NACV incentive amount: `amount = (NACV × BP) / BP_DIVISOR` where `BP_DIVISOR = 10000` (only if BP > 0).
- NACV range parsing: strings like `"$1.00 MM - <$5.00 MM"` converted using `NACV_MM_MULTIPLIER = 1_000_000`; `"$50.00 MM +"` → `(value×1e6, inf)`. Matching row selects BP where `min_val <= nacv < max_val`.
- Ticket-type mapping (Excel label → contract band): `US CC→Standard Ticket`, `ROC Tier 1→Large Ticket`, `ROC Tier 2→Ultra Large Ticket`, `ROC Tier 3→Ultra Ultra Large Ticket` (+ `TICKET_TYPE_ALIASES`).
- Fixed BP overrides (`FIXED_BP_MAPPING`): `BD=25, Stryker=25, OLYMPUS=25, Baxter=25, General=35, ROC Tier 1=75, ROC Tier 2=50, ROC Tier 3=10`.
- CHD Actual Calc: `difference = chd_actual − chd_benchmark`; `applicable_bp` = the "below" rule bp if difference<0, the (negated) "above" rule bp if difference>0, else 0; `basis_point_effective = difference × applicable_bp`; `amount = (total_nacv × basis_point_effective) / 10000`.
- CHD CAP Calc: actual forced to 0, `difference = benchmark − 0`; positive difference uses the "below" bp; same amount formula.
- CHD rule extraction uses regex (`CHD_OR_PATTERN`, `CHD_POSITIVE_BP_PATTERN`, `CHD_NEGATIVE_BP_PATTERN`) to detect "+X bps if below Y days / −Z bps if above W days".
- Validation thresholds: `CHD_MIN=0.0`, `CHD_MAX=1000.0` days; `NACV_MIN=0.0`, `NACV_MAX=1e12`; `BP` range −1000..1000; file size 100 bytes..16MB.
**API Endpoints / Routes:** `GET /` (upload), `POST /upload` (validate+parse+compute+store, render results), `POST /recalculate_chd` (recompute CHD from session, no re-upload), `GET /export` (download `NACV_Calculation_Report_YYYYMMDD_HHMMSS.xlsx`).
**Data Model / Storage:** Word table parsed to `{headers, rows}` (first column = NACV range; ticket columns matched by substring `Standard Ticket`/`ST-BIR`, `Large Ticket`, `Ultra Large Ticket`, `Ultra Ultra Large Ticket`; cell values like `"25 bps"`/`"No Incentive"`). Excel parsed to `[{label, nacv}]`. Result `{calculations:[{label,type,nacv,bp,amount}], total_nacv, total_amount}`. Export sheets: (1) NACV Calculation (+TOTAL), (2) CHD Calculation (Actual + CAP), (3) Contract Terms, (4) Source Data. Session keys: `calculation_results, chd_calculation, table_info, chd_info, excel_nacv_data, chd_actual, word_filename, excel_filename`.
**Key Features:** Dual-document parsing with multiple fallback strategies (largest-table fallback, alternate NACV-column detection); fixed-BP vendor overrides; CHD Actual vs CAP dual calculation; recompute CHD without re-upload; styled 4-sheet Excel export; rotating file logging; comprehensive input validation and filename sanitization.
**Project Structure (key files):** `app.py` (routes, `calculate_nacv_incentives`, `calculate_chd_adjustments`, `create_excel_export`); `config.py` (constants, mappings, regex, error messages); `parsers.py` (`WordDocumentParser`, `ExcelParser`); `validators.py` (`FileValidator`, `CHDValidator`, `NACVValidator`, `BPValidator`, `validate_upload_request`); `logger.py`; `templates/upload.html`, `results.html`; `build.sh`, `render.yaml`, `runtime.txt`, `start.bat`.

Business knobs: `BP_DIVISOR=10000`, `NACV_MM_MULTIPLIER=1_000_000`, ticket/fixed-BP mappings, validation ranges, log settings (`LOG_FILE=nacv_calculator.log`, 10MB×5).
**Setup / Run / Deploy:** Local `pip install -r requirements.txt` then `python app.py` → http://localhost:5000 (or `start.bat`). Deploy (Render): `build.sh` (`pip install`, `mkdir -p uploads __pycache__`), start `gunicorn app:app`; `render.yaml` provisions a 1GB persistent disk at `/opt/render/project/src/uploads`, sets `SECRET_KEY` (generated), `DEBUG=False`, `PORT=10000`.
**Integrations / External Services:** None (fully self-contained).
**Known Limitations / Caveats / Security Notes:** Regex/heuristic Word parsing can silently return empty tables/None benchmark on non-standard contracts (errors logged, processing continues with partial data). **Key Algorithms / Logic / Formulas / Thresholds:**
